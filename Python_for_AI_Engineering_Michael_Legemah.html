The five Python ideas every AI codebase leans on

syntax_primer.py
"""syntax_primer.py: the five Python ideas every AI codebase leans on.

Run it with:  python syntax_primer.py   (no API keys needed)
"""
import asyncio
import functools
import time
from typing import Any, AsyncIterator, Iterator, TypedDict


# 1) TYPE HINTS + TypedDict: a labelled shape for a dictionary
class Message(TypedDict):
    role: str      # "system", "user" or "assistant"
    content: str


history: list[Message] = [
    {"role": "user", "content": "Hi!"},
]
settings: dict[str, Any] = {"temperature": 0.2, "max_tokens": 512}


# 2) DECORATORS: a function that wraps another function
def timed(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"{func.__name__} took {elapsed:.4f}s")
        return result
    return wrapper


@timed
def count_words(text: str) -> int:
    return len(text.split())


# 3) GENERATORS: produce values one at a time with `yield`
def chunk_text(text: str, size: int) -> Iterator[str]:
    for start in range(0, len(text), size):
        yield text[start:start + size]


# 4) CLASS INHERITANCE: a child class reuses and extends a parent
class BaseTool:
    name = "base"

    def __init__(self, description: str) -> None:
        self.description = description

    def run(self, query: str) -> str:
        raise NotImplementedError("Child classes must implement run()")


class EchoTool(BaseTool):
    name = "echo"

    def run(self, query: str) -> str:
        return f"[{self.name}] {query}"


# 5) ASYNC / AWAIT: start many slow waits at once instead of one by one
async def fake_llm_call(prompt: str, delay: float) -> str:
    await asyncio.sleep(delay)          # stands in for a network call
    return f"answer to: {prompt}"


async def stream_tokens(answer: str) -> AsyncIterator[str]:
    for word in answer.split():
        await asyncio.sleep(0.05)       # pretend each token arrives over the wire
        yield word


async def main() -> None:
    print(count_words("agents call tools in a loop"))
    print(list(chunk_text("abcdefghij", size=4)))
    print(EchoTool("repeats its input").run("hello"))

    started = time.perf_counter()
    answers = await asyncio.gather(
        fake_llm_call("What is RAG?", 1.0),
        fake_llm_call("What is an agent?", 1.0),
    )
    print(answers, f"in {time.perf_counter() - started:.1f}s")   # ~1.0s, not 2.0s

    async for token in stream_tokens(answers[0]):
        print(token, end=" ", flush=True)
    print()


if __name__ == "__main__":
    asyncio.run(main())

  1. L5
    import asyncio

    asyncio is Python's built-in engine for running many waiting tasks at once on a single thread. Every async AI SDK (OpenAI, Anthropic, LangGraph's ainvoke) runs on top of it.

  2. L6
    import functools

    functools holds helpers for working with functions. We need functools.wraps so a decorated function keeps its real name and docstring.

  3. L7
    import time

    time.perf_counter() is a high-resolution stopwatch. Use it, not time.time(), for measuring latency, because it never jumps when the system clock changes.

  4. L8
    from typing import Any, AsyncIterator, Iterator, TypedDict

    Type hints are labels, not rules: Python doesn't enforce them at runtime, but editors, linters, Pydantic and LangGraph read them. Any means "anything goes", Iterator and AsyncIterator describe generators, and TypedDict describes a dictionary with known keys.

  5. L12–14
    class Message(TypedDict):

    A TypedDict declares the shape of a plain dictionary. At runtime a Message is still an ordinary dict; the class just documents that it must have a role string and a content string. This is exactly how LangGraph defines agent state and how chat messages are typed in SDKs.

  6. L17
    history: list[Message] = [

    Read the colon as "is a": history is a list of Message dictionaries. The square brackets say what's inside the container.

  7. L20
    settings: dict[str, Any] = {"temperature": 0.2, "max_tokens":…

    dict[str, Any] means "keys are strings, values can be anything". It's the most common hint in AI code because model parameters mix floats, ints and strings.

  8. L24
    def timed(func):

    A decorator is just a function that takes a function and returns a new one. timed receives the original function as func.

  9. L25
    @functools.wraps(func)

    Copies func's name and docstring onto the wrapper. Without it, every decorated function would report its name as "wrapper", which breaks logs, and in frameworks like Strands breaks the tool name the model sees.

  10. L26
    def wrapper(*args, **kwargs):

    *args collects any positional arguments into a tuple and **kwargs collects keyword arguments into a dict, so the wrapper can sit in front of any function signature.

  11. L27–31
    start = time.perf_counter()

    The wrapper runs code before the real call (start the clock), calls the original with the same arguments, runs code after (stop the clock, print), then hands back the original result untouched. Retries, tracing, caching and tool registration are all built this way.

  12. L32
    return wrapper

    The decorator returns the new function. The original isn't modified; it's wrapped.

  13. L35–36
    @timed

    The @timed line is shorthand for count_words = timed(count_words). From here on, calling count_words actually calls the wrapper.

  14. L41
    def chunk_text(text: str, size: int) -> Iterator[str]:

    -> Iterator[str] promises this function produces strings one at a time. Any function containing yield is a generator: calling it doesn't run the body, it returns a paused object you pull values from.

  15. L42
    for start in range(0, len(text), size):

    range(0, len(text), size) counts 0, size, 2×size… so each loop pass starts a new slice.

  16. L43
    yield text[start:start + size]

    yield hands one chunk to whoever is looping, then freezes the function exactly here until the next value is requested. Nothing is stored in a list, so you can chunk a 2 GB file with almost no memory.

  17. L47
    class BaseTool:

    A class bundles data (attributes) and behaviour (methods). BaseTool is the parent: it defines what every tool must look like.

  18. L48
    name = "base"

    A class attribute: shared by every instance unless a child overrides it.

  19. L50–51
    def __init__(self, description: str) -> None:

    __init__ runs when you create an object, e.g. EchoTool("..."). self is the object being built, so self.description stores the value on that specific instance. -> None says it returns nothing.

  20. L54
    raise NotImplementedError("Child classes must implement run()")

    The parent deliberately refuses to work. This forces every child class to supply its own run, the same contract LangChain's BaseTool and LangGraph's BaseCheckpointSaver use.

  21. L57
    class EchoTool(BaseTool):

    The parentheses mean inherits from. EchoTool gets __init__ for free and only overrides what differs: its name and its run method. Module 3's DynamoDB saver does exactly this with LangGraph's base class.

  22. L65
    async def fake_llm_call(prompt: str, delay: float) -> str:

    async def creates a coroutine function. Calling it doesn't run it; it returns a coroutine object that only runs when awaited or scheduled on the event loop.

  23. L66
    await asyncio.sleep(delay) # stands in for a network…

    await means "pause me here and let the event loop run other tasks until this finishes". A real API call pauses the same way while bytes travel over the network, which is why one thread can juggle hundreds of LLM calls.

  24. L70–73
    async def stream_tokens(answer: str) -> AsyncIterator[str]:

    An async def with yield is an async generator: it produces values over time and may await between them. This is the exact shape of a streaming LLM response.

  25. L82–83
    answers = await asyncio.gather(

    asyncio.gather starts both coroutines at once and waits for all of them, returning results in the order you passed them in. Two 1-second calls finish in about 1 second total, not 2.

  26. L88
    async for token in stream_tokens(answers[0]):

    async for pulls values from an async generator, awaiting each one. end=" " keeps tokens on one line and flush=True pushes them to the screen immediately, which is how chat UIs show text appearing word by word.

  27. L93–94
    if __name__ == "__main__":

    This guard runs main() only when you execute the file directly, not when another file imports it. asyncio.run creates the event loop, runs main to completion, and shuts the loop down cleanly.

💡 Concept Analogy

Async is one waiter, many tables. A synchronous waiter takes an order, stands in the kitchen until the food is ready, delivers it, then goes to the next table. An async waiter takes table 1's order, hands it to the kitchen, and immediately takes table 2's order while the first meal cooks. await is the moment the waiter says "I'll check back" and walks away.

A decorator is gift wrapping: the present inside is unchanged, but everyone who receives it handles the wrapping first. A generator is a PEZ dispenser, one candy per click instead of the whole pack in your hand. Inheritance is a franchise manual: every branch follows the head-office template and only rewrites the pages that are local.

Key settings

TypedDict vs dataclass

TypedDict is still a dict (great for JSON and LangGraph state); a dataclass is a real object with attribute access.

gather vs TaskGroup

asyncio.TaskGroup (3.11+) cancels siblings when one fails; gather(return_exceptions=True) collects failures instead.

Generator memory

A list holds everything at once; a generator holds one item. Use generators for chunking and streaming.

Core client initialisation: async OpenAI and Anthropic SDKs

OpenClose

One shared, long-lived client per provider, with explicit timeouts and retries, called concurrently with asyncio.gather and streamed token by token. This is the foundation every other module sits on.

Problem it solves

Default clients wait up to 10 minutes on a hung request, a new client per call leaks connections, and calling two providers one after another doubles user-facing latency.

What you get

Both providers answer in parallel in the time of the slower one, failures retry automatically with backoff, and nothing hangs longer than 30 seconds.
llm_clients.py
"""llm_clients.py: async OpenAI + Anthropic clients with production defaults.

pip install openai anthropic httpx
export OPENAI_API_KEY="sk-..."
export ANTHROPIC_API_KEY="sk-ant-..."
"""
import asyncio
import os

import httpx
from anthropic import AsyncAnthropic
from openai import AsyncOpenAI

# Model names change often, so read them from the environment with a sensible default.
OPENAI_MODEL = os.getenv("OPENAI_MODEL", "gpt-4.1-mini")
ANTHROPIC_MODEL = os.getenv("ANTHROPIC_MODEL", "claude-sonnet-5-5")

# 30s to finish a request, but give up after 5s if we can't even connect.
TIMEOUT = httpx.Timeout(30.0, connect=5.0)

openai_client = AsyncOpenAI(
    api_key=os.environ["OPENAI_API_KEY"],
    timeout=TIMEOUT,
    max_retries=3,          # SDK retries 408/409/429/5xx with exponential backoff
)

anthropic_client = AsyncAnthropic(
    api_key=os.environ["ANTHROPIC_API_KEY"],
    timeout=TIMEOUT,
    max_retries=3,
)

SYSTEM_PROMPT = "You are a concise assistant for an AI engineering team."


async def ask_gpt(question: str, temperature: float = 0.2) -> str:
    response = await openai_client.chat.completions.create(
        model=OPENAI_MODEL,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": question},
        ],
        temperature=temperature,
        max_completion_tokens=400,
    )
    return response.choices[0].message.content or ""


async def ask_claude(question: str, temperature: float = 0.2) -> str:
    response = await anthropic_client.messages.create(
        model=ANTHROPIC_MODEL,
        system=SYSTEM_PROMPT,
        messages=[{"role": "user", "content": question}],
        temperature=temperature,
        max_tokens=400,
    )
    return "".join(block.text for block in response.content if block.type == "text")


async def stream_claude(question: str) -> str:
    pieces: list[str] = []
    async with anthropic_client.messages.stream(
        model=ANTHROPIC_MODEL,
        system=SYSTEM_PROMPT,
        messages=[{"role": "user", "content": question}],
        max_tokens=400,
    ) as stream:
        async for text in stream.text_stream:
            print(text, end="", flush=True)
            pieces.append(text)
    print()
    return "".join(pieces)


async def main() -> None:
    question = "In two sentences, what is retrieval-augmented generation?"
    try:
        gpt_answer, claude_answer = await asyncio.gather(
            ask_gpt(question),
            ask_claude(question),
        )
        print("GPT:", gpt_answer, "\n")
        print("Claude:", claude_answer, "\n")
        await stream_claude("Give me one tip for writing good tool descriptions.")
    finally:
        await asyncio.gather(openai_client.close(), anthropic_client.close())


if __name__ == "__main__":
    asyncio.run(main())

💡 Concept Analogy

A client is a company phone line to a supplier. You set it up once, with a policy: "if nobody picks up in 5 seconds, hang up; if a call runs past 30 seconds, end it; if the line is busy, try again up to three times, waiting a little longer each time." You don't install a new phone line for every call.

asyncio.gather is calling both suppliers on two handsets at once instead of finishing one call before dialing the next. Temperature is how adventurous the supplier is allowed to be: at 0 they always quote the catalogue price, at 1 they start improvising.

Key settings

temperature

0–0.3 for extraction, routing and tool use; 0.7+ for creative work. Some reasoning models fix it and reject the parameter.

timeout

Total read budget. Long outputs need more, or switch to streaming.

max_retries

SDK-level retries on 429/5xx with backoff. Add your own retry for errors the SDK won't retry.

max_tokens

Required for Anthropic. Caps cost and the worst-case latency of a reply.

Production RAG retrieval: Pinecone semantic search + OpenSearch keyword search

OpenClose

Embed the question, query a Pinecone namespace for meaning, query OpenSearch with BM25 for exact words, run both at the same time, and merge them with Reciprocal Rank Fusion into one numbered context block for the LLM.

Problem it solves

Pure vector search misses exact terms like SKUs, error codes and names, and pure keyword search misses paraphrases. Either alone puts the wrong passages in front of the model, which is where most RAG hallucinations start.

What you get

Hybrid retrieval that catches both "refund window" and "money back within 30 days", isolated per tenant, with a traceable score per passage.
rag_retrieval.py
"""rag_retrieval.py: OpenAI embeddings + Pinecone semantic search + OpenSearch
keyword search, fused into one ranked list with Reciprocal Rank Fusion (RRF).

pip install openai pinecone opensearch-py
export OPENAI_API_KEY=...  PINECONE_API_KEY=...
export OPENSEARCH_HOST=search-xyz.us-east-1.es.amazonaws.com
export OPENSEARCH_USER=...  OPENSEARCH_PASSWORD=...
"""
import asyncio
import os
from dataclasses import dataclass, field

from openai import AsyncOpenAI
from opensearchpy import OpenSearch
from pinecone import Pinecone

EMBED_MODEL = "text-embedding-3-small"      # returns 1536-dimensional vectors
PINECONE_INDEX = os.getenv("PINECONE_INDEX", "kb-docs")
OPENSEARCH_INDEX = os.getenv("OPENSEARCH_INDEX", "kb-docs")

openai_client = AsyncOpenAI()               # reads OPENAI_API_KEY automatically
pc = Pinecone(api_key=os.environ["PINECONE_API_KEY"])
vector_index = pc.Index(PINECONE_INDEX)

search_client = OpenSearch(
    hosts=[{"host": os.environ["OPENSEARCH_HOST"], "port": 443}],
    http_auth=(os.environ["OPENSEARCH_USER"], os.environ["OPENSEARCH_PASSWORD"]),
    use_ssl=True,
    verify_certs=True,
    timeout=10,
)


@dataclass
class Passage:
    doc_id: str
    text: str
    source: str
    scores: dict[str, float] = field(default_factory=dict)


async def embed(texts: list[str]) -> list[list[float]]:
    response = await openai_client.embeddings.create(model=EMBED_MODEL, input=texts)
    return [item.embedding for item in response.data]


async def semantic_search(question: str, tenant: str, top_k: int = 5) -> list[Passage]:
    [query_vector] = await embed([question])
    result = await asyncio.to_thread(        # Pinecone client is blocking: run it off the event loop
        vector_index.query,
        vector=query_vector,
        top_k=top_k,
        include_metadata=True,
        namespace=tenant,                    # one namespace per customer keeps data isolated
        filter={"status": {"$eq": "published"}},
    )
    return [
        Passage(
            doc_id=match.id,
            text=match.metadata["text"],
            source=match.metadata.get("source", "unknown"),
            scores={"cosine": match.score},
        )
        for match in result.matches
    ]


async def keyword_search(question: str, tenant: str, top_k: int = 5) -> list[Passage]:
    body = {
        "size": top_k,
        "query": {
            "bool": {
                "must": {
                    "multi_match": {
                        "query": question,
                        "fields": ["title^2", "text"],   # a title match counts double
                    }
                },
                "filter": [
                    {"term": {"tenant": tenant}},
                    {"term": {"status": "published"}},
                ],
            }
        },
        "_source": ["text", "source"],
    }
    response = await asyncio.to_thread(search_client.search, index=OPENSEARCH_INDEX, body=body)
    return [
        Passage(
            doc_id=hit["_id"],
            text=hit["_source"]["text"],
            source=hit["_source"].get("source", "unknown"),
            scores={"bm25": hit["_score"]},
        )
        for hit in response["hits"]["hits"]
    ]


def reciprocal_rank_fusion(
    result_lists: list[list[Passage]], k: int = 60, top_n: int = 5
) -> list[Passage]:
    fused: dict[str, Passage] = {}
    rrf_scores: dict[str, float] = {}
    for results in result_lists:
        for rank, passage in enumerate(results, start=1):
            rrf_scores[passage.doc_id] = rrf_scores.get(passage.doc_id, 0.0) + 1.0 / (k + rank)
            if passage.doc_id in fused:
                fused[passage.doc_id].scores.update(passage.scores)
            else:
                fused[passage.doc_id] = passage
    ranked_ids = sorted(rrf_scores, key=lambda doc_id: rrf_scores[doc_id], reverse=True)[:top_n]
    for doc_id in ranked_ids:
        fused[doc_id].scores["rrf"] = round(rrf_scores[doc_id], 4)
    return [fused[doc_id] for doc_id in ranked_ids]


def build_context(passages: list[Passage]) -> str:
    return "\n\n".join(
        f"[{number}] ({p.source}) {p.text}" for number, p in enumerate(passages, start=1)
    )


async def retrieve(question: str, tenant: str) -> list[Passage]:
    semantic, lexical = await asyncio.gather(
        semantic_search(question, tenant),
        keyword_search(question, tenant),
    )
    return reciprocal_rank_fusion([semantic, lexical])


async def main() -> None:
    question = "What is the refund window for annual plans?"
    passages = await retrieve(question, tenant="acme")
    for p in passages:
        print(f"{p.doc_id:<12} {p.scores}")

💡 Concept Analogy

A vector database is a library organised by meaning. Instead of shelving by title, the librarian shelves each book next to books about similar ideas, so "getting my money back" sits beside "refund policy" even though they share no words. An embedding is the book's shelf coordinates.

OpenSearch is the card catalogue: perfect when you know the exact words, useless for paraphrases. RRF is asking both librarians for their top five and giving each book points for how high it appears on each list. A book both librarians rank highly wins.

LangGraph orchestration with a custom DynamoDB checkpoint saver

OpenClose

A StateGraph with four nodes, two conditional edges and a retry loop, compiled with a hand-built DynamoDB checkpointer. Every step is snapshotted, so the agent remembers each conversation thread across restarts, servers and days.

Problem it solves

An in-memory agent forgets everything when the container restarts or the next request lands on a different server, and a multi-step run that crashes halfway has to start over.

What you get

Durable, resumable, per-thread memory in a serverless table with no servers to manage, plus a full history of every intermediate state for debugging and time-travel.

# ───────────────────────── 1. Long-term memory: DynamoDB checkpoint saver ─────────────────────────
def _raw(value: Any) -> bytes:
    """boto3 hands binary attributes back wrapped in a Binary object; unwrap to plain bytes."""
    return value.value if hasattr(value, "value") else bytes(value)


class DynamoDBSaver(BaseCheckpointSaver[str]):
    """Stores LangGraph checkpoints in one DynamoDB table.

    Partition key  pk = "<thread_id>#<checkpoint_ns>"   (one conversation)
    Sort key       sk = "CP#<checkpoint_id>"            (a snapshot of state)
                   sk = "WR#<checkpoint_id>#<task>#<n>" (a pending write from a node)
    Checkpoint ids are time-ordered, so sorting by sk sorts snapshots oldest to newest.
    """

    def __init__(self, table_name: str, region: str = "us-east-1") -> None:
        super().__init__()                       # gives us self.serde, LangGraph's serializer
        self.table_name = table_name
        self.dynamodb = boto3.resource("dynamodb", region_name=region)
        self.table = self.dynamodb.Table(table_name)

    def ensure_table(self) -> None:
        try:
            self.dynamodb.create_table(
                TableName=self.table_name,
                KeySchema=[
                    {"AttributeName": "pk", "KeyType": "HASH"},
                    {"AttributeName": "sk", "KeyType": "RANGE"},
                ],
                AttributeDefinitions=[
                    {"AttributeName": "pk", "AttributeType": "S"},
                    {"AttributeName": "sk", "AttributeType": "S"},
                ],
                BillingMode="PAY_PER_REQUEST",
            )
            self.table.wait_until_exists()
        except ClientError as err:
            if err.response["Error"]["Code"] != "ResourceInUseException":
                raise                             # anything other than "already exists" is a real problem

    @staticmethod
    def _ids(config: RunnableConfig) -> tuple[str, str, str]:
        conf = config["configurable"]
        thread_id = conf["thread_id"]
        checkpoint_ns = conf.get("checkpoint_ns", "")
        return thread_id, checkpoint_ns, f"{thread_id}#{checkpoint_ns}"

    def _to_tuple(self, item: dict[str, Any]) -> CheckpointTuple:
        thread_id, checkpoint_ns = item["thread_id"], item["checkpoint_ns"]
        checkpoint_id = item["sk"][len("CP#"):]
        writes = self.table.query(
            KeyConditionExpression=Key("pk").eq(item["pk"])
            & Key("sk").begins_with(f"WR#{checkpoint_id}#")
        )["Items"]
        parent_id = item.get("parent_id")
        return CheckpointTuple(
            config={"configurable": {"thread_id": thread_id, "checkpoint_ns": checkpoint_ns,
                                     "checkpoint_id": checkpoint_id}},
            checkpoint=self.serde.loads_typed((item["cp_type"], _raw(item["cp_data"]))),
            metadata=self.serde.loads_typed((item["md_type"], _raw(item["md_data"]))),
            parent_config=(
                {"configurable": {"thread_id": thread_id, "checkpoint_ns": checkpoint_ns,
                                  "checkpoint_id": parent_id}}
                if parent_id else None
            ),
            pending_writes=[
                (w["task_id"], w["channel"], self.serde.loads_typed((w["val_type"], _raw(w["val_data"]))))
                for w in writes
            ],
        )

    def get_tuple(self, config: RunnableConfig) -> CheckpointTuple | None:
        _, _, pk = self._ids(config)
        checkpoint_id = config["configurable"].get("checkpoint_id")
        if checkpoint_id:                         # caller asked for one exact snapshot
            item = self.table.get_item(Key={"pk": pk, "sk": f"CP#{checkpoint_id}"}).get("Item")
        else:                                     # otherwise return the newest snapshot
            items = self.table.query(
                KeyConditionExpression=Key("pk").eq(pk) & Key("sk").begins_with("CP#"),
                ScanIndexForward=False,           # newest first
                Limit=1,
            )["Items"]
            item = items[0] if items else None
        return self._to_tuple(item) if item else None

    def list(
        self,
        config: RunnableConfig | None,
        *,
        filter: dict[str, Any] | None = None,
        before: RunnableConfig | None = None,
        limit: int | None = None,
    ) -> Iterator[CheckpointTuple]:
        if config is None:
            raise ValueError("DynamoDBSaver.list needs a config with a thread_id")
        _, _, pk = self._ids(config)
        condition = Key("pk").eq(pk) & Key("sk").begins_with("CP#")
        before_id = (before or {}).get("configurable", {}).get("checkpoint_id")
        if before_id:                             # "CP#" sorts before "WR#", so lt() only sees snapshots
            condition = Key("pk").eq(pk) & Key("sk").lt(f"CP#{before_id}")
        query_args: dict[str, Any] = {"KeyConditionExpression": condition, "ScanIndexForward": False}
        yielded = 0
        while True:
            page = self.table.query(**query_args)
            for item in page["Items"]:
                found = self._to_tuple(item)
                if filter and any(found.metadata.get(k) != v for k, v in filter.items()):
                    continue
                yield found
                yielded += 1
                if limit is not None and yielded >= limit:
                    return
            if "LastEvaluatedKey" not in page:
                return
            query_args["ExclusiveStartKey"] = page["LastEvaluatedKey"]   # fetch the next page

    def put(
        self,
        config: RunnableConfig,
        checkpoint: Checkpoint,
        metadata: CheckpointMetadata,
        new_versions: ChannelVersions,
    ) -> RunnableConfig:
        thread_id, checkpoint_ns, pk = self._ids(config)
        cp_type, cp_data = self.serde.dumps_typed(checkpoint)
        md_type, md_data = self.serde.dumps_typed(metadata)
        item = {
            "pk": pk,
            "sk": f"CP#{checkpoint['id']}",
            "thread_id": thread_id,
            "checkpoint_ns": checkpoint_ns,
            "cp_type": cp_type, "cp_data": cp_data,
            "md_type": md_type, "md_data": md_data,
        }
        parent_id = config["configurable"].get("checkpoint_id")
        if parent_id:
            item["parent_id"] = parent_id
        self.table.put_item(Item=item)
        return {"configurable": {"thread_id": thread_id, "checkpoint_ns": checkpoint_ns,
                                 "checkpoint_id": checkpoint["id"]}}

    def put_writes(
        self,
        config: RunnableConfig,
        writes: Sequence[tuple[str, Any]],
        task_id: str,
        task_path: str = "",
    ) -> None:
        _, _, pk = self._ids(config)
        checkpoint_id = config["configurable"]["checkpoint_id"]
        with self.table.batch_writer(overwrite_by_pkeys=["pk", "sk"]) as batch:
            for index, (channel, value) in enumerate(writes):
                val_type, val_data = self.serde.dumps_typed(value)
                batch.put_item(Item={
                    "pk": pk,
                    "sk": f"WR#{checkpoint_id}#{task_id}#{index:05d}",
                    "task_id": task_id,
                    "channel": channel,
                    "val_type": val_type,
                    "val_data": val_data,
                })

    def get_next_version(self, current: str | None, channel: None = None) -> str:
        current_v = 0 if current is None else int(str(current).split(".")[0])
        return f"{current_v + 1:032}.{random.random():016}"

    # Async twins: boto3 is blocking, so run each call on a worker thread.
    async def aget_tuple(self, config: RunnableConfig) -> CheckpointTuple | None:
        return await asyncio.to_thread(self.get_tuple, config)

    async def alist(
        self,
        config: RunnableConfig | None,
        *,
        filter: dict[str, Any] | None = None,
        before: RunnableConfig | None = None,
        limit: int | None = None,
    ) -> AsyncIterator[CheckpointTuple]:
        found = await asyncio.to_thread(
            lambda: list(self.list(config, filter=filter, before=before, limit=limit))
        )
        for checkpoint_tuple in found:
            yield checkpoint_tuple

    async def aput(self, config, checkpoint, metadata, new_versions) -> RunnableConfig:
        return await asyncio.to_thread(self.put, config, checkpoint, metadata, new_versions)

    async def aput_writes(self, config, writes, task_id, task_path: str = "") -> None:
        await asyncio.to_thread(self.put_writes, config, writes, task_id, task_path)


# ───────────────────────── 2. The workflow: state, nodes, edges ─────────────────────────
class SupportState(TypedDict, total=False):
    question: str
    route: str                                          # "lookup" or "chat"
    context: str
    answer: str
    attempts: int
    history: Annotated[list[dict[str, str]], operator.add]   # reducer: append, never overwrite


KNOWLEDGE_BASE = {
    "refund": "Annual plans can be refunded in full within 30 days of purchase.",
    "sso": "SAML single sign-on is included on the Enterprise plan only.",
    "rate limit": "The API allows 600 requests per minute per workspace.",
}

llm = OpenAI()   # nodes run synchronously inside graph.invoke(), so the sync client fits


def chat(prompt: str, system: str) -> str:
    response = llm.chat.completions.create(
        model=MODEL,
        messages=[{"role": "system", "content": system}, {"role": "user", "content": prompt}],
        temperature=0,
        max_completion_tokens=300,
    )
    return (response.choices[0].message.content or "").strip()


def classify(state: SupportState) -> dict[str, Any]:
    label = chat(
        f"Question: {state['question']}\n"
        "Reply with one word: lookup if it needs company policy facts, otherwise chat.",
        system="You are a request router. Reply with exactly one word.",
    ).lower()
    return {"route": "lookup" if "lookup" in label else "chat", "attempts": 0, "context": ""}


def retrieve(state: SupportState) -> dict[str, Any]:
    question = state["question"].lower()
    hits = [text for topic, text in KNOWLEDGE_BASE.items() if topic in question]
    if not hits and state.get("attempts", 0) > 0:      # second pass: broaden to everything
        hits = list(KNOWLEDGE_BASE.values())
    return {"context": "\n".join(hits)}


def answer(state: SupportState) -> dict[str, Any]:
    recent = state.get("history", [])[-6:]
    transcript = "\n".join(f"{turn['role']}: {turn['content']}" for turn in recent) or "(new conversation)"
    reply = chat(
        f"Conversation so far:\n{transcript}\n\n"
        f"Policy context:\n{state.get('context') or '(none)'}\n\n"
        f"Customer question: {state['question']}",
        system=("You are a support agent. Use the policy context for policy questions. "
                "If you cannot answer, reply exactly: I don't know."),
    )
    return {"answer": reply, "attempts": state.get("attempts", 0) + 1}


def finalize(state: SupportState) -> dict[str, Any]:
    return {"history": [
        {"role": "user", "content": state["question"]},
        {"role": "assistant", "content": state["answer"]},
    ]}


def route_after_classify(state: SupportState) -> str:
    return state["route"]                                # "lookup" or "chat"


def route_after_answer(state: SupportState) -> str:
    unsure = "i don't know" in state["answer"].lower()
    return "retry" if unsure and state["attempts"] < 2 else "done"


def build_graph() -> StateGraph:
    graph = StateGraph(SupportState)
    graph.add_node("classify", classify)
    graph.add_node("retrieve", retrieve)
    graph.add_node("answer", answer)
    graph.add_node("finalize", finalize)

    graph.add_edge(START, "classify")
    graph.add_conditional_edges("classify", route_after_classify,
                                {"lookup": "retrieve", "chat": "answer"})
    graph.add_edge("retrieve", "answer")
    graph.add_conditional_edges("answer", route_after_answer,
                                {"retry": "retrieve", "done": "finalize"})
    graph.add_edge("finalize", END)
    return graph


def main() -> None:
    saver = DynamoDBSaver(TABLE_NAME, region=AWS_REGION)
    saver.ensure_table()
    app = build_graph().compile(checkpointer=saver)

    config = {"configurable": {"thread_id": "customer-42"}}   # one thread = one conversation
    first = app.invoke({"question": "How long is the refund window on annual plans?"}, config)
    print("Agent:", first["answer"])

    second = app.invoke({"question": "Remind me, what did I just ask you about?"}, config)
    print("Agent:", second["answer"])

    saved = app.get_state(config)                    # read straight back from DynamoDB
    print(f"Turns remembered: {len(saved.values['history']) // 2}")
    print(f"Snapshots stored: {sum(1 for _ in saver.list(config))}")


if __name__ == "__main__":
    main()

💡 Concept Analogy

LangGraph is a board game. The nodes are squares, the edges are arrows on the board, and a conditional edge is a square that says "roll: if even, go to Retrieve; if odd, go to Answer". The state is the player's backpack, carried from square to square.

The checkpointer is a save-game slot in the cloud. After every move the game is saved, labelled with your player name (the thread ID). Close the game, switch consoles, come back next week, and you continue from the exact square with the exact backpack. The pending writes are a half-finished turn written on a sticky note, so a crash mid-turn doesn't make you replay moves you'd already made.

DynamoDB caps items at 400 KB. Offload large state to S3 and store a pointer.

Add a TTL attribute to expire old threads automatically and control storage cost.

CrewAI: specialised agents bound to sequential tasks

OpenClose

Three agents with their own role, goal and backstory (researcher, architect, writer), three tasks wired in order with explicit context passing, one custom @tool, and a Pydantic-typed scorecard in the middle so the pipeline produces data, not just prose.

Problem it solves

One giant prompt asked to research, analyse and write at once does all three badly, and its free-text output can't be checked by code.

What you get

A repeatable research-to-decision pipeline where each step is focused, inspectable, and the scoring step returns validated, typed data.
vendor_crew.py
"""vendor_crew.py: three specialised CrewAI agents run three tasks in order,
each task handing its output to the next, ending in a written brief.

pip install crewai
export OPENAI_API_KEY=...      (or ANTHROPIC_API_KEY with an anthropic/ model below)
"""
import json
import os

from crewai import LLM, Agent, Crew, Process, Task
from crewai.tools import tool
from pydantic import BaseModel, Field

MODEL = os.getenv("CREW_MODEL", "openai/gpt-4.1-mini")   # provider/model, e.g. anthropic/claude-sonnet-5-5

# Two LLM configs: a precise one for facts and numbers, a looser one for prose.
precise_llm = LLM(model=MODEL, temperature=0.1)
creative_llm = LLM(model=MODEL, temperature=0.6)

# Illustrative demo numbers, not real list prices. Swap in your own procurement data.
VENDOR_DATA = {
    "pinecone": {"type": "managed vector DB", "price_per_1m_vectors_usd": 70, "hybrid_search": True},
    "opensearch": {"type": "search engine with k-NN", "price_per_1m_vectors_usd": 45, "hybrid_search": True},
    "pgvector": {"type": "Postgres extension", "price_per_1m_vectors_usd": 25, "hybrid_search": False},
}


@tool("Vendor fact sheet")
def vendor_fact_sheet(vendor: str) -> str:
    """Return pricing and capability facts for one vector store vendor.
    Valid vendors: pinecone, opensearch, pgvector."""
    facts = VENDOR_DATA.get(vendor.strip().lower())
    if facts is None:
        return f"No data for '{vendor}'. Valid vendors: {', '.join(VENDOR_DATA)}"
    return json.dumps(facts)


class VendorScore(BaseModel):
    vendor: str
    score: int = Field(ge=1, le=10, description="Overall fit, 1 (poor) to 10 (excellent)")
    reason: str


class Scorecard(BaseModel):
    scores: list[VendorScore]
    recommendation: str


researcher = Agent(
    role="Vector Database Researcher",
    goal="Collect accurate, sourced facts about each vector store for {use_case}",
    backstory=(
        "You spent five years benchmarking search infrastructure. You never guess a number: "
        "if it isn't in the fact sheet, you say it's unknown."
    ),
    tools=[vendor_fact_sheet],
    llm=precise_llm,
    allow_delegation=False,
    max_iter=6,
    verbose=True,
)

analyst = Agent(
    role="Solutions Architect",
    goal="Score each vendor against the constraints of {use_case}",
    backstory="You turn research into decisions, weighing cost, operations and retrieval quality.",
    llm=precise_llm,
    allow_delegation=False,
    verbose=True,
)

writer = Agent(
    role="Technical Writer",
    goal="Write a one-page decision brief an engineering director can read in two minutes",
    backstory="You write plainly, lead with the recommendation and never bury a trade-off.",
    llm=creative_llm,
    allow_delegation=False,
    verbose=True,
)

research_task = Task(
    description=(
        "Use the Vendor fact sheet tool to look up pinecone, opensearch and pgvector. "
        "Summarise type, price per 1M vectors and hybrid search support for each."
    ),
    expected_output="A bullet list with one entry per vendor and its three facts.",
    agent=researcher,
)

analysis_task = Task(
    description=(
        "Using the research, score each vendor from 1 to 10 for {use_case}. "
        "Our team is {team_size} engineers with a budget of ${budget_usd} per month."
    ),
    expected_output="A scorecard with a score and one-sentence reason per vendor, plus a recommendation.",
    agent=analyst,
    context=[research_task],          # receives research_task's output as input
    output_pydantic=Scorecard,        # forces a validated, typed result
)

writing_task = Task(
    description="Write the decision brief for {use_case} from the research and the scorecard.",
    expected_output="Markdown: a one-line recommendation, a comparison table, then risks and next steps.",
    agent=writer,
    context=[research_task, analysis_task],
    output_file="vector_db_brief.md",
)

crew = Crew(
    agents=[researcher, analyst, writer],
    tasks=[research_task, analysis_task, writing_task],
    process=Process.sequential,       # run the tasks one after another, in list order
    verbose=True,
)


if __name__ == "__main__":
    result = crew.kickoff(inputs={
        "use_case": "hybrid RAG over 5M support articles",
        "team_size": 4,
        "budget_usd": 800,
    })
    scorecard: Scorecard = result.tasks_output[1].pydantic
    for entry in scorecard.scores:
        print(f"{entry.vendor:<11} {entry.score}/10  {entry.reason}")
    print("\n", result.raw)
    print("\nTokens used:", result.token_usage)

"""agent_runtime.py: a model-driven Strands agent with @tool functions,
served by the Amazon Bedrock AgentCore Runtime.

pip install strands-agents bedrock-agentcore
Local test:
  python agent_runtime.py
  curl -X POST http://localhost:8080/invocations \
       -H "Content-Type: application/json" \
       -d '{"prompt": "Where is order A-1001 and can I still get a refund?"}'
"""
import json
import os
from datetime import date

from bedrock_agentcore.runtime import BedrockAgentCoreApp, RequestContext
from strands import Agent, tool
from strands.models import BedrockModel

MODEL_ID = os.getenv("BEDROCK_MODEL_ID", "us.anthropic.claude-sonnet-4-5-20250929-v1:0")
REGION = os.getenv("AWS_REGION", "us-east-1")

ORDERS = {
    "A-1001": {"status": "delivered", "delivered_on": "2026-09-20", "total_usd": 129.00},
    "A-1002": {"status": "in transit", "delivered_on": None, "total_usd": 54.50},
}


@tool
def get_order_status(order_id: str) -> str:
    """Look up the shipping status, delivery date and total of a customer order.

    Args:
        order_id: The order number, for example "A-1001".
    """
    order = ORDERS.get(order_id.strip().upper())
    if order is None:
        return f"No order found with id {order_id}."
    return json.dumps(order)


@tool
def refund_eligibility(delivered_on: str, total_usd: float) -> str:
    """Decide whether a delivered order can still be refunded under the 30-day policy.

    Args:
        delivered_on: Delivery date in YYYY-MM-DD format.
        total_usd: The order total in US dollars.
    """
    days = (date.today() - date.fromisoformat(delivered_on)).days
    if days <= 30:
        return f"Eligible: delivered {days} days ago, full refund of ${total_usd:.2f}."
    return f"Not eligible: delivered {days} days ago, past the 30-day window."


model = BedrockModel(
    model_id=MODEL_ID,
    region_name=REGION,
    temperature=0.2,
    max_tokens=1024,
)

SYSTEM_PROMPT = (
    "You are an order-support agent. Always check the order with get_order_status before "
    "answering. Only call refund_eligibility for delivered orders. Be brief and specific."
)

app = BedrockAgentCoreApp()
agents_by_session: dict[str, Agent] = {}


def agent_for(session_id: str) -> Agent:
    """One Agent per session, so two customers never share a conversation history."""
    if session_id not in agents_by_session:
        agents_by_session[session_id] = Agent(
            model=model,
            system_prompt=SYSTEM_PROMPT,
            tools=[get_order_status, refund_eligibility],
            callback_handler=None,        # silence token-by-token console printing
        )
    return agents_by_session[session_id]


@app.entrypoint
def invoke(payload: dict, context: RequestContext) -> dict:
    prompt = payload.get("prompt", "").strip()
    if not prompt:
        return {"error": 'Send a JSON body like {"prompt": "Where is order A-1001?"}'}
    session_id = context.session_id or "local-dev"
    result = agent_for(session_id)(prompt)       # the model decides which tools to call
    return {
        "result": str(result),
        "stop_reason": result.stop_reason,
        "session_id": session_id,
    }


if __name__ == "__main__":
    app.run()          # serves POST /invocations and GET /ping on port 8080

    text: str = ""
    citations: list[dict[str, Any]] = field(default_factory=list)
    steps: list[str] = field(default_factory=list)

def ask_agent(question: str, session_id: str, user_attributes: dict[str, str] | None = None) -> AgentReply:
    reply = AgentReply()
    decoder = codecs.getincrementaldecoder("utf-8")()       # safe across split multi-byte characters
    try:
        response = runtime.invoke_agent(
            agentId=AGENT_ID,
            agentAliasId=AGENT_ALIAS_ID,
            sessionId=session_id,                           # same id = agent remembers the conversation
            inputText=question,
            enableTrace=True,                               # stream the agent's reasoning steps too
            sessionState={"sessionAttributes": user_attributes or {}},
        )
        for event in response["completion"]:               # an EventStream: events arrive one by one
            if "chunk" in event:
                chunk = event["chunk"]
                piece = decoder.decode(chunk.get("bytes", b""))
                print(piece, end="", flush=True)
                reply.text += piece
                for citation in chunk.get("attribution", {}).get("citations", []):
                    for ref in citation.get("retrievedReferences", []):
                        reply.citations.append({
                            "source": ref.get("location", {}),
                            "excerpt": ref.get("content", {}).get("text", "")[:160],
                        })
            elif "trace" in event:
                orchestration = event["trace"].get("trace", {}).get("orchestrationTrace", {})
                if "rationale" in orchestration:
                    reply.steps.append("thought: " + orchestration["rationale"].get("text", ""))
                invocation = orchestration.get("invocationInput", {})
                if "actionGroupInvocationInput" in invocation:
                    action = invocation["actionGroupInvocationInput"]
                    reply.steps.append(f"tool: {action.get('actionGroupName')} {action.get('apiPath') or action.get('function')}")
                if "knowledgeBaseLookupInput" in invocation:
                    reply.steps.append("kb search: " + invocation["knowledgeBaseLookupInput"].get("text", ""))
            elif "returnControl" in event:
                reply.return_control = event["returnControl"]   # agent wants *your* code to run a tool
        reply.text += decoder.decode(b"", final=True)
        print()
    except EventStreamError as err:                         # error raised mid-stream
        raise RuntimeError(f"Agent stream failed: {err}") from err
    except ClientError as err:                              # error raised before streaming started
        code = err.response["Error"]["Code"]
        if code == "ThrottlingException":
            raise RuntimeError("Bedrock is throttling this account; retry later or raise the quota.") from err
        raise
    return reply


def send_tool_result(session_id: str, return_control: dict[str, Any], result: dict[str, Any]) -> AgentReply:
    """Finish a return-of-control turn: hand the tool result back so the agent can answer."""
    invocation = return_control["invocationInputs"][0]["functionInvocationInput"]
    response = runtime.invoke_agent(
        agentId=AGENT_ID,
        agentAliasId=AGENT_ALIAS_ID,
        sessionId=session_id,
        sessionState={
            "invocationId": return_control["invocationId"],
            "returnControlInvocationResults": [{
                "functionResult": {
                    "actionGroup": invocation["actionGroup"],
                    "function": invocation["function"],
                    "responseBody": {"TEXT": {"body": json.dumps(result)}},
                }
            }],
        },
    )
    raw = b"".join(event["chunk"]["bytes"] for event in response["completion"] if "chunk" in event)
    return AgentReply(text=raw.decode("utf-8"))      # join bytes first, then decode once

Async & concurrencyCoreAsync / await

Summarise 100 documents with an LLM as fast as possible, but never send more than 10 requests at once, and don't let one failure kill the batch.

AnswerClose

Wrap each call in an asyncio.Semaphore(10), launch them all with asyncio.gather(return_exceptions=True), then split results into successes and failures by zipping them back with their inputs.
q01.py
import asyncio
import random


async def call_llm(prompt: str) -> str:
    """Stand-in for a real SDK call: slow, and fails about 10% of the time."""
    await asyncio.sleep(random.uniform(0.05, 0.2))
    if random.random() < 0.1:
        raise TimeoutError(f"upstream timeout for {prompt!r}")
    return f"summary of {prompt}"


async def run_batch(prompts: list[str], max_concurrency: int = 10) -> tuple[list[str], list[tuple[str, Exception]]]:
    semaphore = asyncio.Semaphore(max_concurrency)

    async def guarded(prompt: str) -> str:
        async with semaphore:                 # at most max_concurrency calls inside at once
            return await call_llm(prompt)

    results = await asyncio.gather(*(guarded(p) for p in prompts), return_exceptions=True)

    successes, failures = [], []
    for prompt, outcome in zip(prompts, results):   # gather keeps input order
        if isinstance(outcome, Exception):
            failures.append((prompt, outcome))
        else:
            successes.append(outcome)
    return successes, failures


if __name__ == "__main__":
    docs = [f"doc-{i}" for i in range(100)]
    ok, failed = asyncio.run(run_batch(docs, max_concurrency=10))
    print(f"{len(ok)} succeeded, {len(failed)} failed")
    for prompt, err in failed[:3]:
        print(" ", prompt, "->", err)

Why this answer works

asyncio.Semaphore(10) is a counter with 10 permits. async with semaphore takes one and gives it back on exit, even on error, so at most 10 calls are ever in flight. That's how you stay under a provider's concurrency or rate limits while still running everything else in parallel.

return_exceptions=True changes what gather does with errors: instead of raising the first one and abandoning the rest, it puts the exception object in that slot of the results list. gather preserves input order, so zip(prompts, results) lines every outcome up with the prompt that caused it, and you can retry just the failures.

Creating all 100 coroutines up front is fine because they're cheap until they run. The semaphore, not the number of tasks, controls pressure on the API.

What they're probing

Whether you know the difference between concurrency limits and rate limits, and whether you handle partial failure instead of all-or-nothing.

Likely follow-ups
  • How is this different from asyncio.TaskGroup?TaskGroup (Python 3.11+) cancels all sibling tasks when one fails. That's right when the batch is all-or-nothing, wrong here, where you want every document attempted.
  • What if the limit is tokens per minute, not concurrent requests?A semaphore can't express that. Use a token bucket sized in tokens (see the rate-limiter question) and acquire the estimated token count before each call.
  • What about 100,000 documents?Don't create 100k coroutines at once. Feed a fixed pool of N worker tasks from an asyncio.Queue, or use the provider's batch API, which is often half the price for non-urgent work.

Write an async retry decorator with exponential backoff and jitter that only retries errors worth retrying.

AnswerClose

A decorator factory that takes settings, wraps the coroutine in a loop, catches only a whitelist of transient exceptions, sleeps a random delay up to base × 2^(attempt−1), capped, and re-raises on the last attempt.
q02.py
import asyncio
import functools
import random


class TransientError(Exception):
    """Errors worth retrying: throttling, timeouts, 5xx."""


class PermanentError(Exception):
    """Errors not worth retrying: bad request, auth failure, content policy."""


def retry_async(max_attempts: int = 4, base_delay: float = 0.5, max_delay: float = 8.0,
                retry_on: tuple[type[BaseException], ...] = (TransientError,)):
    def decorator(func):
        @functools.wraps(func)
        async def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return await func(*args, **kwargs)
                except retry_on as err:
                    if attempt == max_attempts:
                        raise                                  # out of attempts: surface the error
                    ceiling = min(max_delay, base_delay * 2 ** (attempt - 1))
                    delay = random.uniform(0, ceiling)         # "full jitter"
                    print(f"{func.__name__}: attempt {attempt} failed ({err}); retrying in {delay:.2f}s")
                    await asyncio.sleep(delay)
        return wrapper
    return decorator


calls = {"n": 0}


@retry_async(max_attempts=4, base_delay=0.1)
async def flaky_completion(prompt: str) -> str:
    calls["n"] += 1
    if calls["n"] < 3:
        raise TransientError("429 Too Many Requests")
    return f"answer to {prompt}"


@retry_async(max_attempts=4, base_delay=0.1)
async def bad_request(prompt: str) -> str:
    raise PermanentError("400 invalid model name")


async def main() -> None:
    print(await flaky_completion("hello"))
    try:
        await bad_request("hello")
    except PermanentError as err:
        print("failed fast, no retries:", err)


if __name__ == "__main__":
    asyncio.run(main())

Why this answer works

There are three levels of functions: retry_async(...) takes the settings and returns decorator, which takes the function and returns wrapper, which runs on every call. That extra outer layer is what lets you write @retry_async(max_attempts=4) with arguments.

Only retry what can succeed next time. A 429 or a timeout might; a 400 (bad request) or 401 (bad key) never will, and retrying it just burns time and quota. except retry_on catches only the whitelisted types, so permanent errors fail fast.

Full jitter (random.uniform(0, ceiling)) matters at scale: if 500 clients all get throttled at the same moment and all wait exactly 1, 2, 4 seconds, they retry in lockstep and get throttled again. Randomising spreads them out.

A bare raise inside except re-raises the original exception with its traceback intact.

What they're probing

Decorator mechanics, error classification, and awareness of the thundering-herd problem.

Likely follow-ups
  • The OpenAI and Anthropic SDKs already retry. Why write this?SDK retries cover transport and 429/5xx. You still need retries around your own steps: a whole RAG pipeline, a validation-and-repair loop, or a tool call to an internal API.
  • How would you honour a Retry-After header?Attach the header value to the exception, and if it's present, sleep for max(retry_after, computed_delay).
  • Is retrying always safe?Only if the operation is idempotent. Retrying 'charge the card' can double-charge. Use idempotency keys for writes.

Your primary LLM provider is having an outage. Implement automatic fallback to a second provider that stops hammering the broken one.

Try providers in priority order, each guarded by a circuit breaker. After N consecutive failures a breaker opens and that provider is skipped entirely until a cooldown passes, then one trial request decides whether to close it again.
q03.py
import asyncio
import time
from collections.abc import Awaitable, Callable


class CircuitBreaker:
    """CLOSED: calls go through. OPEN: calls are skipped until cooldown ends.
    HALF-OPEN: after cooldown, one trial call decides whether to close again."""

    def __init__(self, failure_threshold: int = 3, cooldown_s: float = 30.0) -> None:
        self.failure_threshold = failure_threshold
        self.cooldown_s = cooldown_s
        self.failures = 0
        self.opened_at: float | None = None

    @property
    def state(self) -> str:
        if self.opened_at is None:
            return "closed"
        if time.monotonic() - self.opened_at >= self.cooldown_s:
            return "half-open"
        return "open"

    def record_success(self) -> None:
        self.failures = 0
        self.opened_at = None

    def record_failure(self) -> None:
        self.failures += 1
        if self.failures >= self.failure_threshold or self.state == "half-open":
            self.opened_at = time.monotonic()


Provider = tuple[str, Callable[[str], Awaitable[str]], CircuitBreaker]


async def complete_with_fallback(prompt: str, providers: list[Provider]) -> tuple[str, str]:
    errors: list[str] = []
    for name, call, breaker in providers:
        if breaker.state == "open":
            errors.append(f"{name}: circuit open, skipped")
            continue
        try:
            answer = await asyncio.wait_for(call(prompt), timeout=10)
            breaker.record_success()
            return name, answer
        except Exception as err:          # noqa: BLE001 - any provider failure triggers fallback
            breaker.record_failure()
            errors.append(f"{name}: {type(err).__name__}")
    raise RuntimeError("All providers failed: " + "; ".join(errors))


async def primary(prompt: str) -> str:
    raise ConnectionError("503 from primary")


async def secondary(prompt: str) -> str:
    return f"secondary answered: {prompt}"


async def main() -> None:
    providers: list[Provider] = [
        ("openai", primary, CircuitBreaker(failure_threshold=2, cooldown_s=60)),
        ("anthropic", secondary, CircuitBreaker()),
    ]
    for i in range(4):
        used, answer = await complete_with_fallback(f"q{i}", providers)
        print(f"call {i}: {used:<9} primary breaker={providers[0][2].state}")


if __name__ == "__main__":
    asyncio.run(main())

Implement cosine-similarity top-k search over a matrix of embeddings in NumPy, without a Python loop.

AnswerClose

Normalise the query and every row to unit length, take one matrix–vector product to get all similarities, use argpartition to find the top k in linear time, then sort just those k.
q04.py
import numpy as np


def top_k_cosine(query: np.ndarray, matrix: np.ndarray, k: int = 3) -> list[tuple[int, float]]:
    """query: shape (d,)  matrix: shape (n, d)  ->  [(row_index, similarity), ...] best first."""
    if matrix.shape[0] == 0:
        return []
    k = min(k, matrix.shape[0])
    q = query / (np.linalg.norm(query) + 1e-12)                         # unit-length query
    m = matrix / (np.linalg.norm(matrix, axis=1, keepdims=True) + 1e-12)  # unit-length rows
    scores = m @ q                                                       # (n,) cosine similarities
    candidates = np.argpartition(-scores, k - 1)[:k]                     # O(n): unordered top k
    best = candidates[np.argsort(-scores[candidates])]                   # O(k log k): sort just those
    return [(int(i), float(scores[i])) for i in best]

Why this answer works

Cosine similarity is the dot product of two vectors divided by their lengths. Normalising everything to length 1 first means the division disappears, so matrix @ query computes every document's cosine in a single vectorised operation that runs in optimised C, not Python.

keepdims=True keeps the norms as an (n, 1) column so NumPy broadcasts the division across each row. The + 1e-12 prevents dividing by zero for an all-zero vector.

np.argsort on all n scores costs O(n log n). np.argpartition only guarantees the top k are in the first k slots, unordered, in O(n). Then sorting those k is O(k log k). For 10 million vectors and k=5, that difference is real.

Negating the scores (-scores) turns "largest first" into the smallest-first order these functions use.

  • Cosine vs dot product vs Euclidean?On unit-normalised vectors, cosine and dot product rank identically, and Euclidean distance is a monotonic function of them. Match whatever metric the embedding model was trained for.
  • How would you save memory?Store float16 or int8-quantised vectors. You trade a little precision for a 2–4× memory reduction.

How would you measure whether a retrieval change made RAG better? Implement recall@k, precision@k and MRR.

q05.py
def recall_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    if not relevant:
        return 0.0
    return len(set(retrieved[:k]) & relevant) / len(relevant)


def precision_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    top = retrieved[:k]
    return len(set(top) & relevant) / len(top) if top else 0.0


def reciprocal_rank(retrieved: list[str], relevant: set[str]) -> float:
    for rank, doc_id in enumerate(retrieved, start=1):
        if doc_id in relevant:
            return 1.0 / rank
    return 0.0


def evaluate(runs: list[dict], k: int = 5) -> dict[str, float]:
    n = len(runs)
    return {
        f"recall@{k}": sum(recall_at_k(r["retrieved"], r["relevant"], k) for r in runs) / n,
        f"precision@{k}": sum(precision_at_k(r["retrieved"], r["relevant"], k) for r in runs) / n,
        "mrr": sum(reciprocal_rank(r["retrieved"], r["relevant"]) for r in runs) / n,
    }

Write a document chunker that respects sentence boundaries, stays under a token budget, and overlaps neighbouring chunks.

Split into sentences, grow a window until adding the next sentence would exceed the budget, emit the window, carry the last sentence over as overlap, and yield chunks lazily from a generator.

import re
from collections.abc import Callable, Iterator


def approx_tokens(text: str) -> int:
    """Rough rule of thumb: ~4 characters per token for English. Swap in tiktoken for exact counts."""
    return max(1, len(text) // 4)


def chunk_document(text: str, max_tokens: int = 200, overlap_sentences: int = 1,
                   count_tokens: Callable[[str], int] = approx_tokens) -> Iterator[str]:
    sentences = [s.strip() for s in re.split(r"(?<=[.!?])\s+", text) if s.strip()]
    window: list[str] = []
    for sentence in sentences:
        candidate = " ".join(window + [sentence])
        if window and count_tokens(candidate) > max_tokens:
            yield " ".join(window)                          # emit the full chunk
            window = window[-overlap_sentences:] if overlap_sentences else []
            if window and count_tokens(" ".join(window + [sentence])) > max_tokens:
                window = []                                 # overlap alone would overflow: drop it
        window.append(sentence)
    if window:
        yield " ".join(window)

Why this answer works

Splitting mid-sentence produces chunks whose embeddings represent half-thoughts, which retrieve poorly. The regex (?<=[.!?])\s+ splits on whitespace that follows sentence punctuation (a lookbehind), so the punctuation stays attached.

It's a generator (yield), so a 500-page PDF streams through without every chunk held in memory at once.

The edge case: if the overlap sentence plus the next sentence would already overflow, drop the overlap rather than emitting an over-budget chunk.

An LLM streams Server-Sent Events over HTTP. Write an async generator that turns raw byte chunks into text deltas.

AnswerClose

Decode bytes with an incremental UTF-8 decoder, append to a string buffer, split complete events on the blank-line delimiter, keep the incomplete tail in the buffer, parse each data: line as JSON, and stop at [DONE].
q07.py
import asyncio
import codecs
import json
from collections.abc import AsyncIterator


async def fake_network(body: bytes, piece_size: int = 7) -> AsyncIterator[bytes]:
    """Simulates bytes arriving over HTTP in arbitrary-sized pieces."""
    for i in range(0, len(body), piece_size):
        await asyncio.sleep(0)
        yield body[i:i + piece_size]


async def sse_events(byte_stream: AsyncIterator[bytes]) -> AsyncIterator[dict]:
    """Turn a Server-Sent Events byte stream into parsed JSON events."""
    buffer = ""
    decoder = codecs.getincrementaldecoder("utf-8")()   # a piece may end mid-character
    async for piece in byte_stream:
        buffer += decoder.decode(piece)
        while "\n\n" in buffer:                       # a blank line ends one event
            raw_event, buffer = buffer.split("\n\n", 1)
            data_lines = [line[len("data:"):].strip()
                          for line in raw_event.splitlines() if line.startswith("data:")]
            if not data_lines:
                continue
            data = "\n".join(data_lines)
            if data == "[DONE]":
                return
            yield json.loads(data)


async def stream_answer(byte_stream: AsyncIterator[bytes]) -> AsyncIterator[str]:
    async for event in sse_events(byte_stream):
        delta = event.get("delta", "")
        if delta:
            yield delta


async def main() -> None:
    body = (
        'data: {"delta": "Retrieval "}\n\n'
        'data: {"delta": "augmented "}\n\n'
        ': keep-alive comment\n\n'
        'data: {"delta": "generation ✓"}\n\n'
        'data: [DONE]\n\n'
    ).encode()
    tokens = []
    async for token in stream_answer(fake_network(body)):
        print(token, end="", flush=True)
        tokens.append(token)
    print(f"\n{len(tokens)} deltas")


if __name__ == "__main__":
    asyncio.run(main())

Why this answer works

The network has no idea where your events end: one read might hold half an event or three of them. The buffer pattern solves it: append everything, peel off complete events while a \n\n exists, and leave the remainder for the next read.

buffer.split("\n\n", 1) splits once only, returning the first complete event and everything after it.

An incremental decoder is required because bytes can split a multi-byte character such as ✓ across reads. Decoding each piece on its own would crash or corrupt it.

SSE lines that don't start with data: (comments like : keep-alive, or event: lines) are ignored, and [DONE] ends the stream with a plain return, which ends an async generator.

Two generators stacked: sse_events handles the protocol and stream_answer handles the provider's payload shape. Each layer is testable without a network, as the fake byte source shows.

"""A minimal tool-calling agent loop on the Anthropic Messages API.
pip install anthropic   export ANTHROPIC_API_KEY=...
"""
import inspect
import json
import os
from collections.abc import Callable
from typing import Any, get_type_hints

from anthropic import Anthropic

TOOLS: dict[str, Callable[..., Any]] = {}
PY_TO_JSON = {str: "string", int: "integer", float: "number", bool: "boolean"}


def agent_tool(func: Callable[..., Any]) -> Callable[..., Any]:
    """Register a function as a tool. Its docstring and type hints become the schema."""
    TOOLS[func.__name__] = func
    return func


def tool_schemas() -> list[dict[str, Any]]:
    schemas = []
    for name, func in TOOLS.items():
        hints = get_type_hints(func)
        params = inspect.signature(func).parameters
        schemas.append({
            "name": name,
            "description": inspect.getdoc(func) or name,
            "input_schema": {
                "type": "object",
                "properties": {p: {"type": PY_TO_JSON.get(hints.get(p), "string")} for p in params},
                "required": [p for p, spec in params.items() if spec.default is inspect.Parameter.empty],
            },
        })
    return schemas


@agent_tool
def get_weather(city: str) -> str:
    """Get today's weather for a city."""
    fake = {"paris": "18C and sunny", "london": "12C and raining"}
    return fake.get(city.lower(), "no data for that city")


@agent_tool
def convert_c_to_f(celsius: float) -> str:
    """Convert a Celsius temperature to Fahrenheit."""
    return f"{celsius * 9 / 5 + 32:.1f}F"


def run_agent(task: str, max_steps: int = 6) -> str:
    client = Anthropic()
    messages: list[dict[str, Any]] = [{"role": "user", "content": task}]
    for _ in range(max_steps):                                   # hard stop: no infinite loops
        response = client.messages.create(
            model=os.getenv("ANTHROPIC_MODEL", "claude-sonnet-5-5"),
            max_tokens=800,
            tools=tool_schemas(),
            messages=messages,
        )
        messages.append({"role": "assistant", "content": response.content})
        if response.stop_reason != "tool_use":                   # model is done: return the text
            return "".join(b.text for b in response.content if b.type == "text")

        results = []
        for block in response.content:
            if block.type != "tool_use":
                continue
            func = TOOLS.get(block.name)
            try:
                output = func(**block.input) if func else f"Unknown tool {block.name}"
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": str(output)})
            except Exception as err:                             # feed the error back, let the model recover
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "content": f"Error: {err}", "is_error": True})
        messages.append({"role": "user", "content": results})
    return "Stopped: reached the step limit before finishing."

@agent_tool is a registration decorator: it stores the function and returns it unchanged. That's essentially what Strands' @tool and CrewAI's @tool do, plus richer schema generation.

A long-running agent's conversation keeps overflowing the context window. Write a trimmer that keeps the system prompt and the most recent turns within a token budget.

from collections.abc import Callable
from typing import Any

Message = dict[str, Any]


def approx_tokens(message: Message) -> int:
    return max(1, len(str(message["content"])) // 4) + 4     # +4 for role/formatting overhead


def _turns(messages: list[Message]) -> list[list[Message]]:
    """Group messages into units that must be kept or dropped together:
    an assistant message that calls tools plus the tool results that answer it."""
    groups: list[list[Message]] = []
    for msg in messages:
        if msg["role"] == "tool" and groups:
            groups[-1].append(msg)                            # attach result to its tool call
        else:
            groups.append([msg])
    return groups


def trim_history(messages: list[Message], budget: int,
                 count: Callable[[Message], int] = approx_tokens) -> list[Message]:
    system = [m for m in messages if m["role"] == "system"]
    rest = [m for m in messages if m["role"] != "system"]
    used = sum(count(m) for m in system)
    kept: list[list[Message]] = []
    for group in reversed(_turns(rest)):                      # newest first
        cost = sum(count(m) for m in group)
        if used + cost > budget:
            break
        kept.append(group)
        used += cost
    trimmed = [m for group in reversed(kept) for m in group]
    while trimmed and trimmed[0]["role"] != "user":           # history must start on a user turn
        trimmed.pop(0)
    return system + trimmed

Implement an async rate limiter that keeps you under a provider's tokens-per-minute quota while allowing short bursts.

AnswerClose

A token bucket: capacity is the burst size, it refills continuously at quota/60 per second, each request acquires its estimated token count, and if there aren't enough, it sleeps exactly long enough for the refill to cover the shortfall.
q11.py
import asyncio
import time


class TokenBucket:
    """Allows `rate` units per second on average, with bursts up to `capacity`.
    Use units = tokens to respect a provider's tokens-per-minute (TPM) quota."""

    def __init__(self, rate_per_s: float, capacity: float) -> None:
        self.rate = rate_per_s
        self.capacity = capacity
        self.available = capacity
        self.updated = time.monotonic()
        self._lock = asyncio.Lock()

    def _refill(self) -> None:
        now = time.monotonic()
        self.available = min(self.capacity, self.available + (now - self.updated) * self.rate)
        self.updated = now

    async def acquire(self, amount: float = 1.0) -> None:
        if amount > self.capacity:
            raise ValueError(f"request of {amount} exceeds bucket capacity {self.capacity}")
        async with self._lock:                         # one waiter at a time keeps it fair (FIFO)
            while True:
                self._refill()
                if self.available >= amount:
                    self.available -= amount
                    return
                await asyncio.sleep((amount - self.available) / self.rate)


async def call_model(bucket: TokenBucket, request_id: int, est_tokens: int, start: float) -> None:
    await bucket.acquire(est_tokens)
    print(f"t={time.monotonic() - start:4.2f}s  request {request_id} sent ({est_tokens} tokens)")


async def main() -> None:
    tpm = 60_000                                       # e.g. a 60k tokens-per-minute quota
    bucket = TokenBucket(rate_per_s=tpm / 60, capacity=3_000)
    start = time.monotonic()
    await asyncio.gather(*(call_model(bucket, i, 1_000, start) for i in range(6)))

Embedding calls are your biggest cost. Add an async cache with LRU eviction and a TTL, and make sure concurrent identical requests only hit the API once.

AnswerClose

An OrderedDict keyed by a hash of model plus normalised text, moved to the end on every hit and evicted from the front when full, plus an in-flight map of futures so duplicate concurrent requests await the first one instead of calling the API again.
q12.py
import asyncio
import hashlib
import time
from collections import OrderedDict
from collections.abc import Awaitable, Callable


class TTLCache:
    def __init__(self, max_items: int = 10_000, ttl_s: float = 3600) -> None:
        self.max_items = max_items
        self.ttl_s = ttl_s
        self._data: OrderedDict[str, tuple[float, list[float]]] = OrderedDict()
        self.hits = self.misses = 0

    def get(self, key: str) -> list[float] | None:
        entry = self._data.get(key)
        if entry is None or time.monotonic() - entry[0] > self.ttl_s:
            self._data.pop(key, None)
            self.misses += 1
            return None
        self._data.move_to_end(key)                     # mark as most recently used
        self.hits += 1
        return entry[1]

    def put(self, key: str, value: list[float]) -> None:
        self._data[key] = (time.monotonic(), value)
        self._data.move_to_end(key)
        while len(self._data) > self.max_items:
            self._data.popitem(last=False)              # evict least recently used


class CachedEmbedder:
    def __init__(self, embed_fn: Callable[[str], Awaitable[list[float]]], model: str, cache: TTLCache) -> None:
        self.embed_fn, self.model, self.cache = embed_fn, model, cache
        self._in_flight: dict[str, asyncio.Future] = {}

    def _key(self, text: str) -> str:
        normalized = " ".join(text.lower().split())
        return hashlib.sha256(f"{self.model}:{normalized}".encode()).hexdigest()

    async def embed(self, text: str) -> list[float]:
        key = self._key(text)
        if (cached := self.cache.get(key)) is not None:
            return cached
        if key in self._in_flight:                      # same text already being fetched: share it
            return await self._in_flight[key]
        future = asyncio.get_running_loop().create_future()
        self._in_flight[key] = future
        try:
            vector = await self.embed_fn(text)
            self.cache.put(key, vector)
            future.set_result(vector)
            return vector
        except Exception as err:
            future.set_exception(err)
            raise
        finally:
            del self._in_flight[key]


async def main() -> None:
    api_calls = 0

    async def fake_embed(text: str) -> list[float]:
        nonlocal api_calls
        api_calls += 1
        await asyncio.sleep(0.1)
        return [float(len(text)), 0.5]

    embedder = CachedEmbedder(fake_embed, "text-embedding-3-small", TTLCache(max_items=100))
    texts = ["What is RAG?", "what is  rag?", "What is RAG?", "Define agents"]
    await asyncio.gather(*(embedder.embed(t) for t in texts))
    await embedder.embed("WHAT IS RAG?")
    print(f"5 requests -> {api_calls} API calls (duplicates shared one in-flight call or hit the cache)")


if __name__ == "__main__":
    asyncio.run(main())

Why this answer works

OrderedDict remembers insertion order. move_to_end(key) marks an entry as recently used and popitem(last=False) evicts the oldest, which is LRU in a few lines.

The key includes the model name: vectors from different embedding models aren't interchangeable, so a model upgrade must never return a cached old vector. Normalising whitespace and case raises the hit rate, and hashing keeps keys short.

functools.lru_cache doesn't work on async functions the way you'd hope: it caches the coroutine object, which can only be awaited once. That's why this is a hand-written class.

Request coalescing: the first caller creates a Future and stores it in _in_flight; concurrent callers with the same key await that future instead of calling the API. The finally clause always removes it, success or failure.

The walrus operator := assigns and tests in one expression: fetch the cached value and check it isn't None.

Threads, asyncio or multiprocessing: which would you use for LLM calls, for local tokenisation of a million documents, and why? Show it.

AnswerClose

I/O-bound work like API calls uses asyncio (or threads), because the GIL is released while waiting on the network. CPU-bound pure-Python work like tokenising and regex PII scans uses a process pool, because each process has its own interpreter and GIL. You can mix them with loop.run_in_executor.
q14.py
import asyncio
import hashlib
import time
from concurrent.futures import ProcessPoolExecutor


def cpu_heavy_fingerprint(text: str) -> str:
    """Pure-Python CPU work (think: tokenising, PII regex scans, dedup hashing)."""
    digest = text.encode()
    for _ in range(400_000):
        digest = hashlib.sha256(digest).digest()
    return digest.hex()[:12]


async def io_heavy_call(i: int) -> int:
    await asyncio.sleep(0.5)                   # network wait: the GIL is released while waiting
    return i


async def main() -> None:
    docs = [f"document {i}" for i in range(8)]

    start = time.perf_counter()
    await asyncio.gather(*(io_heavy_call(i) for i in range(50)))
    print(f"asyncio: 50 network-bound calls in {time.perf_counter() - start:.2f}s")

    start = time.perf_counter()
    [cpu_heavy_fingerprint(d) for d in docs]
    serial = time.perf_counter() - start

    loop = asyncio.get_running_loop()
    start = time.perf_counter()
    with ProcessPoolExecutor() as pool:        # separate processes, separate GILs
        await asyncio.gather(*(loop.run_in_executor(pool, cpu_heavy_fingerprint, d) for d in docs))
    parallel = time.perf_counter() - start
    print(f"CPU work: serial {serial:.2f}s vs process pool {parallel:.2f}s")


if __name__ == "__main__":
    asyncio.run(main())

Why this answer works

The GIL (global interpreter lock) lets only one thread execute Python bytecode at a time per process. Waiting on a socket releases it, which is why asyncio can run 50 network calls in the time of one.

CPU-bound Python code never waits, so threads take turns rather than running in parallel. A ProcessPoolExecutor starts separate processes, each with its own GIL, so work spreads across cores. On a multi-core machine, the process-pool time drops roughly with the number of cores (the snippet's output depends on your hardware).

loop.run_in_executor(pool, func, arg) bridges the two worlds: an async program hands CPU work to the pool and awaits the result without blocking the event loop.

Processes aren't free: arguments and results are pickled between processes, and startup costs time. Batch work into reasonably large pieces.

Libraries like NumPy and many tokenizers written in Rust or C release the GIL internally, so threads can parallelise them. Measure before assuming.

  • Embedding a million documents: which model?It's I/O-bound against an API, so use asyncio with a concurrency limit plus batching (many texts per request), or the provider's batch API.
